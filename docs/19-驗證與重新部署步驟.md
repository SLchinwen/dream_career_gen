# 驗證與重新部署步驟

> 改過程式（例如加入「目前總監／這屆」的日期對齊）後，要**重新部署**新程式才會生效。部署完成後再依下列方式**驗證**。

---

## 一、需要重新部署嗎？

**要。** 程式碼或設定有改動，都要重新部署後，伺服器上跑的才是新版本。

- **Rails（dream_career_gen）**：改過 ReplyService、日期邏輯等 → 要重新部署。
- **Python bot**：改過 `bot/main.py`（例如日期對齊）→ 若您有部署 bot，也要重新部署該服務。

---

## 二、怎麼重新部署

### 若是 Rails（dream_career_gen，Cloud Run）

1. 在 **dream_career_gen** 專案資料夾：
   ```bash
   git add .
   git commit -m "加入目前總監/這屆的日期對齊（依系統日期推算扶輪年度）"
   git push
   ```
2. 到 **GCP Console** → **Cloud Build** 看建置是否成功，再到 **Cloud Run** 看服務是否已更新（或等幾分鐘讓部署跑完）。

### 若是 Python bot（自己主機或另一台服務）

- 若在本機跑：改完 `main.py` 後**重啟**程式（關掉再執行 `python main.py`）。
- 若已部署到雲端（例如另一台 Cloud Run、Railway）：在該專案 `git push` 觸發部署，或依該平台的「重新部署」流程操作。

---

## 三、怎麼驗證（確認日期對齊有生效）

### 1. 先確認 API 有通

用 **curl** 或 **Postman** 打您的 stage1/reply：

- **URL**：`https://您的 Cloud Run 網址/stage1/reply`（或本機 `http://localhost:3000/stage1/reply`）
- **Method**：POST  
- **Body（JSON）**：`{ "message": "今年地區年會什麼時候" }`

應得到 HTTP 200，且 JSON 有 `reply`、`intent`。

### 2. 驗證「目前總監／這屆」會依今天年度回答

打同一支 API，改問：

- **Body**：`{ "message": "目前總監是誰" }` 或 `{ "message": "這屆總監是誰" }`

**檢查**：回覆裡的總監姓名與年度，應對應**今天日期所屬的扶輪年度**（例如今天在 2025-26 年度內，就應是 2025-26 的總監，不是 2024-25 或 2026-27）。

若回答的年度正確，就代表日期對齊已生效。

### 3. 本機先驗證再部署（可選）

若想先確認再上線：

1. 在 dream_career_gen 本機執行 `ruby bin/rails server`（或 Python bot 本機執行 `python main.py`）。
2. 用上述同樣的 Body 打 `http://localhost:3000/stage1/reply`（或 bot 的 port）。
3. 確認「目前總監」回覆的年度正確後，再執行「二、怎麼重新部署」把程式推上線。

---

## 四、簡短對照

| 項目 | 做法 |
|------|------|
| **要重新部署嗎？** | 要，改過程式或知識庫就要重新部署才會生效。 |
| **Rails 重新部署** | 在 dream_career_gen 專案 `git add` → `git commit` → `git push`，等 Cloud Build 跑完。 |
| **只改了 rid3510 知識庫** | 先 `cd rid3510` → commit → `git push origin main`；再回主專案 `git add rid3510` → commit → push（見第五節）。 |
| **觸發重新部署（無新碼）** | `git commit --allow-empty -m "chore: 觸發重新部署"` → push。 |
| **驗證 API 有通** | POST /stage1/reply，Body `{ "message": "今年年會什麼時候" }`，有 200 和 reply 即可。 |
| **驗證日期對齊** | POST /stage1/reply，Body `{ "message": "目前總監是誰" }`，看回覆是否為「今天」所屬扶輪年度的總監。 |

完成上述部署與驗證後，就代表已重新部署並確認「目前總監／這屆」會依系統日期對齊。

## 五、更新 RID3510 知識庫後的部署

RID3510 聊天服務的**知識庫**（意圖對照、.md 檔案）放在**子模組 rid3510** 裡。若你改動了 `rid3510/docs/` 或 `rid3510/rag-intent-paths.yaml`，需要兩步才會讓雲端用到新內容。

### 步驟 1：把變更推送到 Rid3510 本 repo

在 dream_career_gen 專案內進入子模組，提交並推送：

```bash
cd rid3510
git status
git checkout main
git add .
git commit -m "說明本次知識庫變更（例如：新增綠色奇蹟與扶輪服務）"
git push origin main
```

（若子模組目前是 detached HEAD，可先 `git checkout main`，再 `git merge <剛才的 commit>` 或依實際分支操作。）

### 步驟 2：更新 dream_career_gen 的子模組指向並推送

回到主專案，把「子模組指向的 commit」提交並推送，觸發 Cloud Build 重新建置：

```bash
cd ..
git add rid3510
git commit -m "更新 rid3510 子模組：納入最新知識庫"
git push origin main
```

Cloud Build 建置時會執行 `git submodule update --init --recursive`，把當時指向的 rid3510 commit 一併打進映像，因此**步驟 1 一定要先推**，否則建置可能取不到新 commit。

### 僅改 dream_career_gen 程式（未改 rid3510）時

若只改了意圖辨識（`app/services/rid3510/intent_detector.rb`）或 ReplyService、Controller 等，**不必**動子模組，只要在主專案：

```bash
git add .
git commit -m "說明變更"
git push origin main
```

### 只想觸發重新部署（程式與子模組都沒新變更）

可打一個空 commit 觸發建置：

```bash
git commit --allow-empty -m "chore: 觸發重新部署"
git push origin main
```
