# 21. 服務導覽與發布治理

> 同一台伺服器可能同時部署多種網頁與 API 供測試或對外使用。本文件規範**主網頁導覽頁**的用途，以及**發布／部署新 API 或網頁時**如何將服務加入導覽，維持單一入口與可追溯性。

---

## 一、目的與範圍

| 項目 | 說明 |
|------|------|
| **導覽頁** | 首頁（`/` 或 `get /nav`）列出「網頁服務」與「API」兩大區塊，每項含名稱、路徑、說明與連結（網頁可點選進入）。 |
| **適用對象** | 同機多服務：夢想職人照、RID3510 聊天、People of Action 評分、各 API 等。 |
| **治理目標** | 發布新網頁或新 API 時，依本辦法更新導覽，避免遺漏、方便測試與對外說明。 |

---

## 二、導覽資料來源

- **設定檔**：`config/service_nav.yml`
- **結構**：
  - `meta`：`title`、`description`（選填）、`summary`（選填，上方摘要，例如「綠色奇蹟提供 AI 相關服務…」）
  - `pages`：網頁服務列表，每筆 `name`、`path`、`description`、`updated_at`（選填，格式 YYYY-MM-DD 或 YYYY-MM-DD HH:MM）
  - `apis`：API 列表，每筆 `name`、`path`、`method`（如 POST）、`description`、`updated_at`（選填）
- **導覽頁呈現**：網頁服務與 API 以收合區塊（`<details>`）呈現，可點選展開／收合；每項若有 `updated_at` 會顯示「更新：日期」。頁尾註明「綠色奇蹟公益服務網提供」。

範例見 `config/service_nav.yml`；新增服務時**僅需編輯此 YAML**，無須改 view 程式。

---

## 三、發布新 API 或網頁時：加入導覽的步驟

1. **完成開發與路由**
   - 在 `config/routes.rb` 新增路徑，並完成對應 controller／view 或 API。
2. **編輯 `config/service_nav.yml`**
   - **網頁**：在 `pages` 下新增一筆，填寫 `name`、`path`（如 `/rid3510/chat`）、`description`，選填 `updated_at`。
   - **API**：在 `apis` 下新增一筆，填寫 `name`、`path`、`method`、`description`，選填 `updated_at`。
   - 既有項目有更新時，可一併修改該筆的 `updated_at`，導覽頁會顯示更新時間。
3. **提交與部署**
   - `git add config/service_nav.yml`，commit，push。部署後首頁導覽即會顯示新項目。

**命名與說明建議**

- `name`：簡短、可辨識（例如「RID3510 聊天」「stage1/reply（RID3510）」）。
- `description`：一句話說明用途或適用情境，方便測試者與外部對接方理解。

---

## 四、技術備忘

- **首頁**：`root "pages#index"`，view 為 `app/views/pages/index.html.erb`。
- **導覽連結**：在 `app/views/layouts/application.html.erb` 中，非首頁的 pages 會顯示「← 服務導覽」連結回首頁。
- **同路徑多用途**：若同一 path 同時供網頁與 API 使用，可只在 `pages` 或 `apis` 中擇一列出，或兩邊都列（例如 stage1/reply 列在 API，聊天模擬頁列在 pages）。

---

## 五、檢查清單（發布新服務時）

- [ ] 路由已新增並可正常存取
- [ ] 已編輯 `config/service_nav.yml`，在 `pages` 或 `apis` 新增一筆
- [ ] `name`、`path`、`description`（及 API 的 `method`）填寫完整；有需要可填 `updated_at`
- [ ] 已 commit 並 push，部署後在首頁確認新項目顯示正確

---

**維護約定**：若調整導覽結構（例如新增欄位或區塊），請同步更新本文件與 `app/views/pages/index.html.erb`。
