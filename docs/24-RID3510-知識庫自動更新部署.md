# RID3510 知識庫自動更新部署設計

> 當 **Rid3510**（GitHub 知識庫 repo）有文件更新時，如何讓已發布的 RID3510 聊天機器人**自動**用到新知識庫？本文件說明現況、目標與三種設計方案。

---

## 一、現況

- **dream_career_gen** 把 **rid3510** 當成 **git submodule**，建置時 Cloud Build 執行 `git submodule update --init --recursive`，會拉取 **dream_career_gen 當時記錄的那個 commit** 的 rid3510 內容。
- 因此：只要沒人更新 dream_career_gen 裡的「子模組指向」，雲端映像用的知識庫就不會變；Rid3510 repo 再怎麼更新，**已部署的聊天機器人都不會自動拿到新檔案**。

---

## 二、目標

- Rid3510 知識庫（例如 `docs/`、`rag-intent-paths.yaml`）在 **Rid3510 的 GitHub repo** 有更新並 push 到 main（或指定分支）後，**不需手動到 dream_career_gen 做 submodule 更新與 push**，就能讓下一次（或立即）部署的聊天機器人使用**最新知識庫**。

---

## 三、方案比較

| 方案 | 觸發時機 | 優點 | 缺點 |
|------|----------|------|------|
| **A. Rid3510 push 時更新主專案子模組** | Rid3510 的 main 有 push | 知識庫一更新就排程部署，延遲低 | 需在 Rid3510 或主專案設 GitHub Actions，且要有寫入 dream_career_gen 的權限（PAT） |
| **B. 排程更新子模組** | 每日／每週定時 | 不需改 Rid3510 repo，只在 dream_career_gen 排程即可 | 知識庫更新後最多要等一個排程週期才部署 |
| **C. 建置時永遠拉最新 rid3510** | 每次建置 dream_career_gen 時 | 不必改子模組指向，建置即最新 | 同一主專案 commit 可能建出不同映像（較難重現）；需確保 Rid3510 main 穩定 |

以下以 **方案 A** 與 **B** 為主（推薦），**C** 為替代選項。

---

## 四、方案 A：Rid3510 有 push 時，自動更新 dream_career_gen 子模組並觸發部署

### 流程

1. 有人在 **Rid3510** 的預設分支（如 main）push 新 commit。
2. **GitHub Actions** 被觸發（在 Rid3510 或 dream_career_gen 均可，見下）。
3. Action 做：
   - checkout **dream_career_gen**（需可寫權限），
   - 在 dream_career_gen 裡執行 `git submodule update --remote rid3510`（或 `git pull origin main` 於 rid3510 目錄），
   - 若有 submodule 指向變更，則 `git add rid3510`、commit、push 到 dream_career_gen 的 main。
4. dream_career_gen 的 push 觸發 **Cloud Build** → 建置新映像並部署 → 聊天機器人即使用**最新 Rid3510 知識庫**。

### 實作方式一：在 **Rid3510** repo 建 GitHub Actions

- **觸發**：`on: push: branches: [ main ]`（Rid3510 的 main）。
- **步驟**：  
  - 用 `actions/checkout` 拉 dream_career_gen（需 **Personal Access Token, PAT**，或 GitHub App token，具寫入 dream_career_gen 的權限）。  
  - 在 dream_career_gen 裡：
    - `git submodule update --init --recursive`
    - `cd rid3510 && git fetch origin && git checkout origin/main`（或 `git submodule update --remote rid3510`）
    - 回到根目錄，若 `git status` 有 rid3510 變更，則 `git add rid3510`、`git commit -m "chore: 更新 rid3510 子模組至最新 main"`、`git push origin main`。
- **秘密**：在 Rid3510 的 Settings → Secrets 建立 `DREAM_CAREER_GEN_PAT`（或類似名稱），為對 **dream_career_gen** 有 push 權限的 PAT。

### 實作方式二：在 **dream_career_gen** 用 `repository_dispatch` 由 Rid3510 觸發

- 在 **dream_career_gen** 加一個 workflow，觸發條件為 `repository_dispatch`（例如 `event: sync-rid3510`）。
- 在 **Rid3510** 的 push workflow 裡，最後一步用 `repository_dispatch` 呼叫 dream_career_gen 的 API（需 dream_career_gen 的 PAT 或 GitHub App），帶 event 名稱。
- dream_career_gen 的 workflow 被觸發後，執行上述「submodule update → commit → push」邏輯。

兩種方式都是：**Rid3510 一 push，就驅動 dream_career_gen 更新子模組並 push，再由既有 Cloud Build 完成部署**。

---

## 五、方案 B：排程更新子模組（每日／每週）

- 在 **dream_career_gen** 加一個 GitHub Actions workflow，用 `schedule` 觸發（例如每天 UTC 0:00）。
- 步驟：
  - checkout dream_career_gen（需 PAT 才能 push）。
  - `git submodule update --remote rid3510`（或進入 rid3510 做 fetch + checkout origin/main）。
  - 若有變更：`git add rid3510`、commit、push。
- 這樣 **不需改 Rid3510 repo**；Rid3510 只要照常 push，下次排程跑時就會把最新 commit 拉進 dream_career_gen 並觸發建置。

缺點是：知識庫更新後，最多要等一個排程間隔（例如一天）才會部署。

---

## 六、方案 C：建置時永遠拉最新 rid3510（可選）

- 修改 **Cloud Build** 的步驟：在 `git submodule update --init --recursive` 之後，對 rid3510 再執行一次「拉取最新 main」：
  - 例如在子模組目錄執行 `git fetch origin && git checkout origin/main`，或 `git submodule update --remote rid3510`。
- 如此**每次建置**都會帶入當時 Rid3510 main 的最新內容，不必改 dream_career_gen 的 submodule 指向。
- 注意：
  - 同一 dream_career_gen commit 在不同時間建置，可能得到不同映像（較不具可重現性）。
  - Rid3510 的 main 若有不穩定提交，會直接影響生產環境；可改為拉取指定 **tag**（如 `knowledge-2026-02`）以平衡「更新」與「穩定」。

---

## 七、建議與前置

- **推薦**：以 **方案 A** 為主（Rid3510 push 即觸發更新 + 部署），必要時再加 **方案 B** 當備援（例如每週排程同步一次），確保不會漏跟。
- **必要前置**：
  - 一個對 **dream_career_gen** 具 **push** 權限的 GitHub PAT（或 GitHub App），並在執行自動更新的 repo（Rid3510 或 dream_career_gen）的 Secrets 中設定好。
  - dream_career_gen 的 Cloud Build 已綁定「main 分支 push 即建置並部署」，這樣子模組更新後 push 才會自動部署。

---

## 八、小結

| 要達成的效果 | 做法 |
|--------------|------|
| Rid3510 知識庫一更新，聊天機器人就自動用新內容 | Rid3510 push 時用 GitHub Actions 更新 dream_career_gen 的 rid3510 子模組並 push（方案 A），由既有 Cloud Build 完成部署。 |
| 不想在 Rid3510 加 workflow | 在 dream_career_gen 用排程（方案 B）定期 `submodule update --remote` 再 commit + push。 |
| 建置時永遠用最新知識庫、可接受非完全可重現 | 在 Cloud Build 內建置前對 rid3510 做 fetch + checkout latest（方案 C），必要時改為拉 tag。 |

### 本專案已提供的 workflow（方案 A＋B）

在 **dream_career_gen** 已新增 **`.github/workflows/sync-rid3510.yml`**：

- **排程**：每日 00:00 UTC（約台灣 08:00）執行一次，若有新 commit 就更新子模組並 push，觸發 Cloud Build（**方案 B**）。
- **手動**：在 GitHub Actions 頁面可「Run workflow」。
- **由 Rid3510 觸發（方案 A）**：Rid3510 的 push workflow 可呼叫 GitHub API 發送 `repository_dispatch`，event 類型 `sync-rid3510`，即可立即觸發 dream_career_gen 同步子模組並 push。

**必要設定**：在 dream_career_gen 的 **Settings → Secrets and variables → Actions** 新增 **`REPO_PAT`**，值為對 **dream_career_gen** 具 push 權限的 GitHub Personal Access Token（scope 至少 `repo`）。若 Rid3510 要觸發，需另備對 dream_career_gen 有 `workflow` 觸發權限的 PAT，在 Rid3510 的 Secrets 中使用。

**Rid3510 即時觸發（已提供）**：在 **Rid3510 子模組**裡已新增 `.github/workflows/trigger-dream-career-sync.yml`，push 到 Rid3510 的 main 時會自動呼叫 dream_career_gen 的 `repository_dispatch`。你要做的是：

1. **把這支 workflow 推送到 Rid3510 repo**  
   檔案在 dream_career_gen 的 `rid3510/.github/workflows/trigger-dream-career-sync.yml`。在 `rid3510` 目錄裡執行：
   ```bash
   cd rid3510
   git add .github/workflows/trigger-dream-career-sync.yml
   git commit -m "Add workflow: push 時觸發 dream_career_gen 同步子模組"
   git push origin main
   ```
2. **在 Rid3510 的 GitHub Settings → Secrets and variables → Actions** 新增兩個 Secrets：
   - **`DREAM_CAREER_GEN_PAT`**：對 **dream_career_gen** 有 `repo` 權限的 Personal Access Token（用於觸發 workflow）。
   - **`DREAM_CAREER_GEN_REPO`**：目標 repo，值為 `owner/repo`，例如 `SLChinwen/dream_career_gen`（請改成你的帳號／repo 名稱）。

完成後，每次 push 到 Rid3510 的 main，約一兩分鐘內 dream_career_gen 會同步子模組並觸發 Cloud Build，聊天機器人即會用最新知識庫。
